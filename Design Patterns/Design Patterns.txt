Singleton Design pattern:
=========================
Singleton pattern belongs to creational Type pattern.
This pattern is used, when we need to ensure that only one object of particular class need to be created.   
It provides global access to an instance of an object, and It guarantees that, no more than one instance of that type can ever be created.
Single thread to access the singleton pattern:

Strategy Design Pattern (Behavioral Pattern) (refer link - https://www.youtube.com/watch?v=sdT2LkbrJtc)

Strategy is plan of action designed to achieve a specific goal.
Strategy Pattern says, program to an Interface and not to an Implementation.

For ex. In BBM Application, for LOB Phone, customers will be having different discount Strategies while buying a phone product.
If customer is buying a Phone On special vacation day, based on the starttime and endtime different discounts will be applicable.

Strategy 1) 8AM to 12noon -> something 10% discount
Strategy 2) 12noon to 4pm -> something 20% discount
Strategy 3) 4pm to 8pm -> something 30% discount
Strategy 4) After 8pm -> No discount

	int getFinalBill(int BillAmount);

Factory Design Pattern (Creational Pattern) (refer link : https://www.youtube.com/watch?v=yDEmb5XYc_s )
------------------------
Define an Interface for creating an Object, but let subclasses decide which class to instantiate.

This pattern resolve two problems from below example.
1) Lot of scattered new keyword:    (Problem 1 is solved by introducing class called clsFactoryPattern)
2) Client is aware of all TV types: (Problem 2 is solved by introducing Interface. So that Client will Not have to directly talk to concrete class)
									 

if(TVType == "SateliteTV")
{
  obj= new ClsSateliteTV();
}
if(TVType == "FibeTV")
{
  obj= new ClsFibeTV();
}

Here if we want to create a new TV type as IPTV, again have to recompile a client. So how do we resolve these problem? Factory Design Pattern

Problem 1: to remove all new keyword, create clsFactoryPattern class.
			ex. class clsFactoryPattern
			{
				getTV(TVType tvType);
			}
			Depending on the tvType, it creates objects for either ClsSateliteTV or ClsFibeTV, with this all the new keyword from client is removed.
			
Problem 2: All the concrete classes i.e. ClsFibeTV, ClsSateliteTV are inherited by Interface, client is only aware of interface.
			ex. interface ITvType
			{
				void printTV();
			}
so tomorrow if I add one more class ex. ClsIPTV, client doesn't really want to know what type of TV it's, client will just be knowing Interface(ITvType).

Repository Design Pattern

Repository Pattern is used to separate data access layer(DAL) from controller using intermediate layer.

Using an example of an MVC application, & the Entity Framework.
We use the database context directly inside the controllers. This creates tight coupling between the controller and the data access layer.
Any change related to the data-access layer can break the controller code.

To implement this pattern, we can either use the approach of having a one-repository per model, which means, each entity of the database will have its own repository or we can use a generic repository, that can be used by all the entities of the database.

For our example, we will be using the generic repository
---------------------------------------------------------
//Here TEntity is the generic type that can be any entity of the database.

public class GenericRepository<TEntity> : IGenericRepository<TEntity>         //  where TEntity is class
{
	private DatabaseEntities dbContext;
	
	public GenericRepository(DatabaseEntities _dbContext)
	{
		dbContext=_dbContext;
	}
}

Facade Design Pattern (https://www.youtube.com/watch?v=Ah3ig3ysLZA)

Answers in different way:
	- Facade hides the complexities of the system and provides an interface to the client from where the client can access the system.
	- The Facade design pattern simplifies the interface to a complex system; because it is usually composed of all the classes which make up 
	  the subsystems of the complex system.

    How Facade design pattern simplifies the interface to a complex systems:
    Client submit Just Postal code -> Facade design pattern will take this request to all these complex systems.
